# backend/sandbox.py

## Original Path
`backend/sandbox.py`

## Purpose
Provides an isolated environment wrapper and logic to execute user-submitted code against various testcases safely, and compares outputs to determine verdicts (AC, WA, etc.).

## Imports
- `subprocess`: Used to spawn parallel processes for code execution.
- `tempfile`: To create temporary scripts for run isolation.
- `json` & `re`: For parsing and serializing test cases.

## Classes
N/A (Functional implementation).

## Functions
- `parse_txt_file(file_path)`: Reads and parses rough `.txt` testcases into python data structures (int, float, array, scalar).
- `execute_user_code(...)`: The core engine taking source code string and pumping it into a spawned subprocess with specific timeouts and inputs.
- `compare_outputs(...)`: Matches the expected vs actual output of the subprocess execution to determine accuracy.
- `extract_testcases_from_folders(...)`: Maps the directory structures generated by `file_manager.py` into executable testcase arrays.

## Execution Notes
Execution bounds and sandbox policies (like limits on disk access or memory limits) are heavily reliant on the host OS executing the python script.

## Modification Risks
Modifying subprocess timeout or arguments can lead to security vulnerabilities (unbounded host resource usage) or infinite loops. Improper `os` module handling might expose the server to path traversal exploits.
